# Test coverage matrix (M19)

This file maps every testing requirement in `project.md` ("# PHASE 15: TESTING" and "## Step 12: Testing") to the tests that cover it. The test files and test names were taken from the test sources (`docs/TEST_INVENTORY.md`, generated by `python3 tools/test_inventory.py`), and the doubtful ones were checked by reading the test bodies. No test was run to write this file.

Every backend test runs with `Http::preventStrayRequests()` (`backend/tests/TestCase.php`), so an unfaked HTTP call fails the test. The app tests use fake repositories and the recorded contract fixtures (`backend/tests/Feature/MobileContract`, `application/test/features/fixture_contract_test.dart`). Neither suite calls a provider.

## Status values

- **Covered**: automated tests exercise the behaviour against the real code and the real MySQL database.
- **Covered with mocks; live sandbox verification is M20**: the adapter and every documented response are tested with `Http::fake` (or, for n8n, the Laravel side only), but the provider has never been called. This applies to the payment gateways, Reloadly, GA4, Search Console, FCM and n8n.
- **Partially covered**: part of the requirement has no test. The reason is given.
- **Not covered here**: needs something this machine does not have (a device, iOS, credentials, Lighthouse, an n8n runtime).

Paths: backend tests are under `backend/tests/`, app tests under `application/test/`. Manual steps (S.., A..) refer to `docs/MANUAL_TEST_CHECKLIST.md`.

Notable gaps, in order of risk:

1. Nothing external has been called: payment gateways, Reloadly, Open Exchange Rates, GA4, Search Console, FCM and n8n are proven against recorded or documented responses only (M20).
2. PayPal payments have no reconciliation test (`payments:reconcile-open` / `reconcile-daily` with a PayPal payment). Suggested test: a PayPal payment whose webhook read timed out is settled by `payments:reconcile-open`, mirroring the Stripe test.
3. The on-device app suite (`application/integration_test`, 6 journeys plus the Arabic purchase journey and the frame-timing test) has never run.
4. The MCP server suite was not part of the final run, and the server has not been run against a live Laravel instance.

## What the automated suites cannot prove

- **Live integrations.** Stripe, PayPal, Paymob, Reloadly, Open Exchange Rates, GA4 Measurement Protocol, Google Search Console OAuth and reporting, and FCM are tested only against `Http::fake`. Whether the real APIs accept our requests, whether the signatures of real webhook deliveries verify, and how the providers behave on errors are unverified until the sandbox checks in M20. The Stripe browser Payment Element has never been loaded.
- **Real devices.** The Flutter tests run on the host with faked platform channels: secure storage, the biometric key store (ECDSA P-256 in hardware), `FLAG_SECURE` screenshot blocking, clipboard clearing on the OS, deep links and app links, push delivery and notification taps, device-integrity (root) detection and frame timing. The `integration_test` journeys need an emulator; the frame budgets need a physical device in profile mode.
- **iOS.** No iOS build, simulator or device exists here: Face ID, the iOS capture-hiding overlay, universal links, APNs through FCM and the `apple-app-site-association` behaviour on a device are untested.
- **Lighthouse.** No Lighthouse run exists (not installed). M18 recorded only a manual headless-Chrome timing check; Performance, SEO and Accessibility scores are open for M20.
- **The n8n runtime.** The 58 workflows are validated statically (`N8nWorkflowValidationTest`, `n8n/scripts/validate-workflows.mjs`); none has been executed, so credentials, node behaviour, schedules and the alert channel (BD9) are unproven.
- **The MCP server end to end.** It has not been started against a running Laravel; its own suite (mocked Laravel API) passed its re-run, 34/34.
- **Production operations.** Queue workers under Supervisor, the scheduler on a server, Redis, Nginx and SSL, backups and restore, real mail delivery, and GeoIP behind Cloudflare (`CF-IPCountry` was injected by hand in the manual run) are M20 items.
- **Real-world fulfilment.** No real code has been bought or delivered; the preview data used fixture codes.
