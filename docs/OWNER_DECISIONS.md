# Owner decisions

These are binding product decisions from the owner. Each one says where it is built. Newer entries go at the bottom.

## 2026-11-10: answers to the M-A8 design questions

| # | Question | Owner answer | Decision as built | Where |
|---|---|---|---|---|
| 1 | Currency shown and charged | Show each user prices in their country's currency; charge in the gateway currency: **Paymob charges EGP, every other gateway charges USD**. | **Display:** the first visit picks the display currency from the visitor's country (GeoIP country → country currency, only if that currency is active with a fresh rate, otherwise USD). A saved choice (cookie, profile, `X-Currency`) always wins, and the switcher stays available. **Payment:** fixed per gateway. Paymob always charges EGP and Stripe, PayPal and the wallet charge USD. The `charge_display_currency_only` restriction on Paymob is removed, and Paymob is offered for any display currency, still subject to country and eligibility rules. Checkout shows the display amount and the exact charged amount ("You will be charged E£… / $…"). Conversion uses the existing rate snapshot and margin floor, once per order. | Backend change "OD-1", run after M12; web checkout (M12 or M13); app checkout (M-A13) |
| 2 | Digits in Arabic | Keep Western digits (123). | As designed: Latin digits everywhere, with left-to-right marks around amounts in RTL text. | Web and app |
| 3 | Store policy blocks in-app purchase | Send the user to the website. | Build a "Complete purchase on boxcards.shop" state behind a remote flag in `/app/config`. It opens the product or cart on the web in the system browser, and is enabled only if store review requires it. | Backend app config flag (OD-1), app (M-A13) |
| 4 | Guest checkout | Must log in to check out. | **App:** no guest checkout. Checkout starts by signing in or registering, and the cart is kept and merged on login. Guest order access by email and OTP stays for orders placed earlier on the web. **Web:** pending owner confirmation, because the original spec has guest checkout. | App (M-A13); web depends on the answer |
| 5 | Rooted or jailbroken devices | PM decides. | **Warn, don't block.** A one-time warning sheet appears on rooted or jailbroken devices. Code reveal stays allowed but always requires recent password or biometric confirmation, and a device-integrity flag is sent with reveal requests and stored in the reveal audit log so the risk engine can act. Screen-capture protection is on for code screens. Reason: many gamers root their devices, and blocking would lose legitimate buyers, while the server-side audit, rate limits and re-auth protect the codes. | App (M-A14), backend audit field (OD-1) |
| 6 | Biometric unlock | Yes. | Optional fingerprint or Face ID. It is offered after the first login and can be turned off in Security settings. It unlocks the app after 5 minutes in the background, and on a supported device it can satisfy the code-reveal re-auth (via the stored refresh credential, never by storing the password). If biometrics change, it falls back to the password. | App (M-A10, M-A16) |
| 7 | Code auto-hide | Follow market practice. | Gift-card stores keep codes viewable in the account and mask them by default. Password managers hide on background and clear the clipboard after about 60–90 seconds. Built: codes are masked by default; **auto-hide after 60 seconds**, and immediately when the app goes to the background or the screen is left; content is blurred in the app switcher; **the clipboard is cleared after 60 seconds**; screenshots are blocked on Android and the content is hidden during capture on iOS. | App (M-A14); web reveal (M13): mask, auto-hide after 60 seconds, hide on tab switch |
| 8 | Home banner | Follow market practice. | **Auto-advance every 5 seconds**, with a pause on touch, swipe or focus. It doesn't resume while the user interacts, stops when off-screen, and doesn't auto-advance when the OS "reduce motion" setting is on. Web: a visible pause/play button (WCAG 2.2.2) and page indicators. | Web (M12), app (M-A11) |
